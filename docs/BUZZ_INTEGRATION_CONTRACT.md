> **SPATHODEA R4 FASTLAB — Phase 2A**
> Version: 0.1.0 | Status: Mock-Only | Date: 2026-08-24

## 1. Overview

The BUZZ gateway is a unified LLM provider abstraction layer that sits between
the SPATHODEA pipeline and any downstream inference backend. It ensures that
the data generation pipeline is **decoupled from provider specifics** — the same
request/response contract applies regardless of whether the backend is a mock,
a local Ollama instance, or a remote API.

```
┌────────────────────────────────────────────────────────────────┐
│                     SPATHODEA Pipeline                          │
│  (generator.py, scorer.py, evaluation/judge.py)                │
└───────────────────────────┬────────────────────────────────────┘
                            │ ProviderRequest
                            ▼
┌────────────────────────────────────────────────────────────────┐
│                      BUZZ Gateway                               │
│                     (buzz_client.py)                            │
│                                                                │
│   ┌──────────┐    ┌─────────────┐    ┌─────────────┐         │
│   │   mock   │    │ local_http  │    │  local_cli  │         │
│   │ (active) │    │   (stub)    │    │   (stub)    │         │
│   └──────────┘    └─────────────┘    └─────────────┘         │
└───────────────────────────┬────────────────────────────────────┘
                            │ ProviderResponse
                            ▼
┌────────────────────────────────────────────────────────────────┐
│                     SPATHODEA Pipeline                          │
│  (continues processing with generated content)                 │
└────────────────────────────────────────────────────────────────┘
```

## 2. Operational Modes

| Mode | Status | Description | Network | API Keys |
|------|--------|-------------|---------|----------|
| `mock` | ✅ Active | Deterministic synthetic responses | None | None |
| `local_http` | 🔲 Stub | HTTP calls to local server (Ollama, vLLM) | Localhost only | None |
| `local_cli` | 🔲 Stub | Subprocess calls to local binary | None | None |

Mode is configured in `config/buzz.yaml` under `buzz.mode`.

## 3. Request Contract (`ProviderRequest`)

Every request sent through the BUZZ gateway MUST conform to this structure:

```python
@dataclass
class ProviderRequest:
    prompt: str                          # REQUIRED — non-empty user input
    system_prompt: Optional[str]         # Optional system instruction
    model: str                           # Target model identifier
    temperature: float                   # 0.0–2.0 (default: 0.8)
    max_tokens: int                      # >= 1 (default: 2048)
    top_p: float                         # 0.0–1.0 (default: 0.95)
    stop_sequences: Optional[list[str]]  # Optional stop strings
    request_id: Optional[str]            # Unique trace identifier
    metadata: dict                       # Arbitrary pipeline context
```

### 3.1 Validation Rules

| Field | Constraint | Rejection Behavior |
|-------|-----------|-------------------|
| `prompt` | Non-empty string (after strip) | Returns error ProviderResponse |
| `temperature` | 0.0 ≤ x ≤ 2.0 | Returns error ProviderResponse |
| `max_tokens` | ≥ 1 | Returns error ProviderResponse |
| `top_p` | 0.0 ≤ x ≤ 1.0 | Returns error ProviderResponse |

### 3.2 Serialization

```python
request.to_dict()   → dict    # For logging / transport
ProviderRequest.from_dict(d)  # Reconstruct from dict
```

## 4. Response Contract (`ProviderResponse`)

Every response returned by the BUZZ gateway MUST conform to this structure:

```python
@dataclass
class ProviderResponse:
    content: str                         # Generated text (empty on error)
    model: str                           # Model that produced this response
    request_id: Optional[str]            # Matches the request's request_id
    finish_reason: str                   # "stop" | "length" | "error" | "mock"
    usage: dict                          # {prompt_tokens, completion_tokens, total_tokens}
    latency_ms: float                    # Response time in milliseconds
    provider: str                        # Backend provider name
    error: Optional[str]                 # Error message (None on success)
    metadata: dict                       # Arbitrary context
```

### 4.1 Success Criteria

A response is **successful** if and only if:
- `error` is `None`
- `finish_reason` ≠ `"error"`
- `content` is non-empty

Access via: `response.is_success` (bool property)

### 4.2 Finish Reasons

| Value | Meaning |
|-------|---------|
| `"stop"` | Natural completion (hit stop sequence or model EOT) |
| `"length"` | Truncated at `max_tokens` |
| `"mock"` | Generated by mock backend (deterministic) |
| `"error"` | Request failed — see `error` field |

### 4.3 Error Responses

Errors are returned as valid `ProviderResponse` objects (never raised as exceptions):

```python
ProviderResponse.error_response(
    error_message="Description of what went wrong",
    request_id="original-request-id",
    provider="mock",
)
```

Pipeline code MUST check `response.is_success` before consuming `response.content`.

## 5. Mock Mode Specification

### 5.1 Behavior

- **No network calls** — all responses generated locally
- **No API keys** — no credentials required or accepted
- **Deterministic** — same prompt always produces same response (when `deterministic: true`)
- **Language-aware** — selects response pool based on `request.metadata["language"]`
- **Configurable error rate** — simulates failures for resilience testing

### 5.2 Response Selection Algorithm

```
1. Extract language from request.metadata["language"] (default: "en")
2. Select response pool: EN (5 templates) | MS (5) | MIXED (3)
3. If deterministic:
     index = int(SHA256(prompt)[:8], 16) % len(pool)
   Else:
     index = random(0, len(pool) - 1)  # seeded RNG
4. Return pool[index] as content
```

### 5.3 Simulated Token Usage

```
prompt_tokens     = len(prompt.split())
completion_tokens = len(content.split())
total_tokens      = prompt_tokens + completion_tokens
```

### 5.4 Configuration Reference (`config/buzz.yaml`)

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `buzz.mode` | string | `"mock"` | Active mode |
| `buzz.mock.model_name` | string | `"buzz-mock-v1"` | Model identifier in responses |
| `buzz.mock.latency_ms` | int | `50` | Simulated latency per request |
| `buzz.mock.deterministic` | bool | `true` | Same prompt → same response |
| `buzz.mock.seed` | int | `42` | RNG seed for non-deterministic mode |
| `buzz.mock.error_rate` | float | `0.0` | Fraction of simulated failures |
| `buzz.mock.response_style` | string | `"helpful"` | Reserved for future styles |
| `buzz.mock.languages` | list | `[en, ms, mixed]` | Supported response languages |

## 6. Client Interface (`BuzzClient`)

### 6.1 Initialization

```python
from adapters.buzz_client import BuzzClient

client = BuzzClient(config=buzz_config["buzz"])
```

### 6.2 Core Methods

| Method | Signature | Description |
|--------|-----------|-------------|
| `send` | `(request: ProviderRequest) → ProviderResponse` | Single request |
| `send_batch` | `(requests: list[ProviderRequest]) → list[ProviderResponse]` | Sequential batch |
| `health_check` | `() → dict` | Full health diagnostics |
| `get_status` | `() → str` | One-word status: PASS / STUB / FAIL |
| `reset` | `() → None` | Reset counter and RNG state |

### 6.3 Properties

| Property | Type | Description |
|----------|------|-------------|
| `mode` | str | Current operational mode |
| `is_mock` | bool | True if running mock mode |
| `request_count` | int | Total requests processed |

## 8. Contract Guarantees

### 8.1 Invariants (MUST hold for all modes)

1. `send()` NEVER raises exceptions — errors are returned as `ProviderResponse`
2. `response.request_id` ALWAYS matches `request.request_id` (when provided)
3. Successful responses ALWAYS have non-empty `content`
4. Error responses ALWAYS have non-empty `error` field
5. `usage` dict ALWAYS contains keys: `prompt_tokens`, `completion_tokens`, `total_tokens`
6. `latency_ms` is ALWAYS ≥ 0
7. `provider` field ALWAYS matches the active mode name

### 8.2 Mock-Specific Guarantees

8. Deterministic mode: identical prompt → identical response (byte-for-byte)
9. No network I/O under any circumstance
10. No file system writes (except configured log directory)
11. No environment variable reads for credentials
12. Response pool is finite and enumerable

### 8.3 Security Guarantees

13. No API keys are stored, read, transmitted, or logged
14. No external HTTP/HTTPS connections are made
15. No subprocess calls are made (even in local_cli stub)
16. No credential scanning of the operating system

## 9. Testing Requirements

Contract tests (`tests/test_buzz_contract.py`) MUST verify:

- [ ] Mock mode returns successful responses for valid requests
- [ ] Deterministic mode produces identical outputs for identical inputs
- [ ] Invalid requests return error responses (not exceptions)
- [ ] Response structure matches ProviderResponse contract
- [ ] Request validation catches all constraint violations
- [ ] Batch processing returns correct number of responses
- [ ] Health check returns expected structure
- [ ] Error rate simulation works correctly
- [ ] Language routing selects correct response pool
- [ ] request_id propagates from request to response
